### 2\. object

- **字段释义**：接口返回数据类型标识

- **固定值**：`chat\.completion`

### 3\. created

- **核心作用**：记录本次对话回答的生成时间

## 二、choices 核心返回字段（对话内容主体）

`choices` 是数组结构，存储模型生成的回答结果，单轮对话默认仅返回1条数据（index=0），为业务核心解析字段。

```json
"choices": [
    {
        "index": 0,
        "message": {...},
        "finish_reason": "stop"
    }
]
```

### 1\. index

- **字段释义**：回答结果序号

- **默认值**：0

- **核心作用**：多结果生成场景下，区分不同回答序号

- **开发用途**：单轮对话固定取 index=0 即可

### 2\. finish\_reason

- **字段释义**：模型结束生成的原因

- **常见枚举值**：
        

    - `stop`：正常生成完毕，无异常

    - `length`：超出最大上下文长度，内容被截断

    - `content\_filter`：内容触发风控过滤，生成终止

- **开发用途**：判断对话是否正常完成，异常场景做提示和重试处理

### 3\. message（核心对话消息体）

存储模型角色、回答内容、思考过程，是**保存上下文、前端展示**的核心字段。

```json
"message": {
    "role": "assistant",
    "content": "用户可见的回答正文",
    "reasoning_content": "模型内部思考推理过程"
}
```

#### role

- **字段释义**：消息角色

- **固定返回值**：`assistant`

- **配套角色**：对话上下文分为 user（用户）、assistant（模型）、system（系统提示词）

- **开发用途**：拼接上下文消息列表，严格区分对话角色，保证多轮对话顺序正确

#### content

- **字段释义**：模型最终输出的**正式回答内容**

- **核心作用**：面向用户的展示文本

- **开发用途**：前端页面展示、对话内容存储、上下文拼接核心字段

#### reasoning\_content

- **字段释义**：模型深层思考、推理、分析的过程文本

- **核心作用**：记录模型解题、应答的思维链路，非用户展示内容

- **开发用途**：调试排查问题、展示AI思考过程、深度日志留存

## 三、usage 计费统计字段（Token消耗）

统计本次对话所有 Token 消耗，用于计费、成本统计、接口限流判断。

```json
"usage": {
    "prompt_tokens": 21,
    "completion_tokens": 543,
    "total_tokens": 564,
    "completion_tokens_details": {
        "reasoning_tokens": 346
    },
    "prompt_tokens_details": {
        "cached_tokens": 0
    },
    "prompt_cache_hit_tokens": 0,
    "prompt_cache_miss_tokens": 21
}
```

### 1\. prompt\_tokens

- **释义**：用户提问 \+ 历史上下文 消耗的输入Token数

- **用途**：统计用户输入成本

### 2\. completion\_tokens

- **释义**：模型生成回答内容消耗的输出Token数

- **用途**：统计模型输出成本

### 3\. total\_tokens

- **释义**：本次对话总消耗Token = 输入Token \+ 输出Token

- **用途**：核心计费统计字段

### 4\. reasoning\_tokens

- **释义**：模型思考过程单独消耗的Token（属于completion子项）

- **用途**：精细化统计思考链路的资源消耗

### 5\. cached\_tokens / 缓存相关字段

- **释义**：提示词缓存命中、未命中Token统计

- **用途**：服务端性能优化统计，前端开发可忽略
